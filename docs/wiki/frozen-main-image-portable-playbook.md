# Как научить агента делать титульные фото для заморозки и охлажденки (переносимая инструкция)

> Написано 2026-09-29 для нового собственного маркетплейса Владимира. Это выжимка из боевого
> конвейера Uncrustables (batch-200, август 2026; 200 листингов). Источники:
> `docs/BUNDLE_FACTORY_FROZEN_MAIN_IMAGE_v2.0.md`, `docs/wiki/uncrustables-listing-rules-canon.md`,
> `docs/wiki/HANDOFF-uncrustables-batch200-2026-08-13.md`,
> код `src/lib/bundle-factory/uncrustables-render-contract.ts`, `audit/frozen-main-qa.ts`.

## 1. Главная идея

Агент **не «рисует красивую картинку товара»**. Он собирает кадр по жёсткому контракту:

```
якорь сцены  +  эталонные фото реальных упаковок  +  контракт-промпт  +  машинный QA  +  fail-closed
```

Всё, что модель придумывает сама, — брак: выдуманные вкусы, искажённый текст на упаковке
Smucker's, лишний гель-пак, не то число коробок. Поэтому каждый шаг ниже убирает у модели свободу.

## 2. Пять частей конвейера (что переносить)

| # | Часть | Что это | У нас сейчас | Для нового сайта |
|---|---|---|---|---|
| 1 | **Якорь сцены** | Один утверждённый владельцем кадр: кулер, логотип, гель-паки, ракурс, свет. Первая референс-картинка ВСЕГДА, проверяется по SHA-256 | Salutem-кулер `anchor-uncrustables.png` | Нужен свой якорь под новый бренд (см. §6) |
| 2 | **Реестр эталонов** | Для каждого товара — реальное фото лицевой стороны упаковки (не инфографика, не сзади) + текст лицевой панели + реальный размер упаковки | `uncrustables-authenticity-registry-v1.json`, каталог `UNCRUSTABLES_FLAVORS` | Общая таблица товаров: id → эталонное фото → точный текст на упаковке |
| 3 | **Контракт-промпт** | Базовый промпт + блок жёстких правил (раскладка по рядам, счёт, запреты) | `buildUncrustablesRetailBoxesContract` | Шаблон, см. §4 |
| 4 | **QA-офицер** | Второй вызов зрения: считает коробки/гели, читает текст, отвечает JSON. 3 голоса, блокирует только то, что большинство увидело одинаково | `frozen-main-qa.ts` | Тот же принцип, см. §5 |
| 5 | **Гейты** | Рецепт математически сходится с картинкой; неодобренное не публикуется; любая правка промпта/якоря/эталонов инвалидирует прошлые одобрения | sealed-манифесты + owner approval | Минимум: манифест (модель, промпт, референсы, SHA) + одобрение владельца на первую картинку каждого «класса» |

## 3. Правила, которые выучены на браке (это самое ценное)

1. **Не выдумывать товар.** Владелец, 2026-07-08: картинка должна быть на 100% тем вкусом, который есть,
   и на ~95% похожа на оригинал. Названия и картинки без выдуманных товаров.
2. **Текст на упаковке модель искажает.** Живые примеры брака: «Reduced Sugor», «BMUCKERS»,
   «Peanut Batter», «KEEP PROZEN», «Chocolatla Flavoura». Лечится двумя вещами:
   (а) в промпт подаётся **точный `frontPanelText`** с побуквенной диктовкой самых длинных слов,
   (б) QA читает текст и бракует. Без (а) модель печатает наше внутреннее название вместо настоящего.
3. **Цифра на бейдже ≠ общее количество.** Печатать на упаковке суммарное число листинга (24, 48…) нельзя.
   Количество передаётся числом видимых упаковок; реальный счётчик упаковки копируется с эталона.
4. **Количество на картинке = количество в рецепте.** `видимые коробки × печатный счёт = qty`.
   Именно это нарушила июльская картинка B0H776M5B5 (4 коробки вместо 6).
5. **Лимиты сцены, доказанные опытом:** не больше 4 видов товара, 11 коробок, 4 ряда, 4 коробки в ряду.
   Сцена 5 видов / 13 коробок провалила 8 рендеров подряд. Расширять — только новым доказанным прогоном.
6. **Один вид в разных упаковках держать в одном ряду**, пока влезает (иначе модель сбивается со счёта:
   9 из 12 отказов были «потеряна/добавлена коробка»). Разный размер упаковки = разный физический размер.
7. **Ретейлерные метки вырезать** («Only at Walmart», Target, ценники, ленты, водяные знаки).
8. **Ровно четыре гель-пака**, два внутри и два снаружи, точный текст на них. Лёд, снег, лужи — запрещены.
9. **Никаких посторонних предметов**, фрукты только как рисунок на упаковке.
10. **Не подставлять «похожее».** Нет эталона / неоднозначный эталон / нет точной раскладки → генерация
    блокируется с явной ошибкой, а не подставляет чужую упаковку.
11. **Донорское фото выбирать осознанно.** Главная ошибка выбора — брать оборот, состав, инфографику,
    лайфстайл вместо лицевой стороны. Каждое фото классифицируется; берётся одиночная прямая лицевая.
12. **Лимит референсов у генератора — 6 штук.** Якорь + до 5 эталонов.
13. **Отбраковка QA: считать «попыткой» только оценённую картинку.** Сбой воркера, недоступное зрение,
    битые байты — не тратят бюджет перегенераций.
14. **Мелкие цифры на бейджах QA-модель путает** (16 из 16 срабатываний «4 vs 8» были ложными).
    Поэтому: общий счёт коробок, число гель-паков, подлинность, орфография крупного текста — **блокеры**;
    поштучные бейджи — **предупреждения** с выборочной ручной проверкой.
15. **Детерминированный композит (вырезал и вставил) отвергнут** для замороженных сцен: логотип, гели,
    перспектива и посадка не совпали с утверждённым результатом. Генерация по референсам — путь.
16. **Числа для планирования бюджета:** ~2–5 мин на картинку; из 323 генераций batch-200 полезных 122
    (~38%) — закладывай ~2.5 попытки на листинг. При подписке ChatGPT Pro стоимость за картинку $0,
    по API — платно. Перед массовым прогоном — канарейка на 1–3 картинки.

## 4. Скелет промпта (шаблон для агента)

Базовая часть (что за кадр):
```
A professional e-commerce main listing image on a pure white background, square 1:1.
The FIRST reference image is the immutable KIT ANCHOR — copy its exact cooler, emblem, wordmark,
four gel packs, camera, lighting and layout only; never copy its products.
The SECOND..Nth reference images are reviewed retail-package art. Copy brand, exact product name,
colors, artwork and the genuine printed pack count verbatim. Do not invent, rebrand or substitute.
Place EXACTLY {N} retail packages inside the cooler, physically seated behind the front inner rim,
shared perspective/lighting, contact shadows. No floating, no gaps, no pasted edges.
Branding of OUR company ONLY on cooler and gel packs — never on third-party packaging.
Subtle frost only. NO loose ice. No people, hands, props, overlay text, watermarks, retailer marks.
```
Контракт-часть (генерируется кодом из рецепта, не вручную):
```
REFERENCE MAPPING: Ref 1 = kit anchor. Ref k = {size}-count package of {product}, front panel reads
  exactly "{frontPanelText}"; draw exactly {boxes} of it, printed badge "{size}" unchanged.
ROW LAYOUT: Row 1 (back): EXACTLY n packages — ... Count: one, two, ... No other package in this row.
TOTAL packages: EXACTLY {total}. Empty row width stays empty.
PACKAGE SCALE: bigger count = physically bigger box.
GEL PACKS: EXACTLY four (1 inside left, 1 inside right, 2 outside front-right). Text letter for letter.
RETAILER FLAGS: omit any retailer roundel.
BRANDING: copy anchor logo pixel-faithfully; never invent a logo.
FRONT TEXT: per-product spelling dictated letter by letter for long or error-prone words.
```
Правило поддержки: **менять строки контракта только вместе с эталонными рендерами** — любая правка
инвалидирует прошлые одобрения (в нашем коде это защищено golden-тестом).

## 5. QA-офицер (шаблон)

Вход: URL картинки + ожидаемый состав (`label`, сколько упаковок, печатный счёт). Второй вызов зрения
возвращает **только JSON** о том, что реально видно:
```
visible_packages_total, packages_per_product[{label,count,badge_digit}],
all_packages_genuine, brand_wordmark_complete, garbled_or_misspelled_text, misspelled_words[],
gel_packs_total, gel_packs_all_say_keep_frozen, cooler_branding_correct,
background_is_pure_white, loose_ice_people_props_or_overlay_text, notes
```
Решение по коду, не по модели: сверка с ожиданием → `hard_fails[]` / `warnings[]`.
Три прогона, блокирует только большинство. **Если зрение недоступно → `verified:false`, картинка не идёт
в публикацию** (для недетерминированной генерации «не смог проверить» = «не публиковать»).
В промпт QA включить: «размытие мелкого текста (<10 px на символ) — это разрешение, а не ошибка».

## 6. Что надо решить именно для нового сайта (ответы меняют работу)

1. **Бренд и якорь.** Кулер сейчас — Salutem. Если новый маркетплейс под другим брендом, нужен новый
   утверждённый якорь-кадр (кулер + логотип + 4 геля) и SHA-256 в контракте. Один раз, вручную, с
   одобрением владельца. Без него агент не стартует.
2. **Охлаждёнка ≠ заморозка.** Готовая часть — только замороженный набор. Для chilled (33–38°F) нужен
   отдельный якорь и текст на гелях («KEEP REFRIGERATED» вместо «KEEP FROZEN»), возможно другое число
   паков. Нельзя просто переименовать заморозку. Сухой товар — вообще без кулера (это другой класс).
3. **Чей рендер.** Наш воркер (Codex/GPT Image 2 на подписке, `mcp.salutem.solutions/codex-image`) или
   API с оплатой за картинку. Влияет на цену перегенераций (см. §3.16).
4. **Правила площадки.** Чистый белый фон и «никаких пропсов» — это требования Amazon к MAIN. На своём
   сайте можно и лайфстайл-титульное; тогда часть запретов (§3.9) можно ослабить, а часть (выдуманный
   товар, искажённый текст, счёт) остаётся всегда — это про честность, а не про площадку.
5. **Откуда эталоны.** У нас — фото ретейлеров (Target и т. п.), проверенные по SHA. Свой источник:
   фото от производителя/поставщика, а не скриншоты.
6. **Кто одобряет.** Наш порядок: владелец одобряет по одной картинке каждого класса раскладки до
   массового прогона; дальше — машинный QA + выборочная ручная проверка.

## 7. Готовый блок инструкции для агента (скопировать в его system prompt)

```
Ты генерируешь титульное фото замороженного/охлаждённого набора. Ты НЕ придумываешь товар.
1. Входные данные: рецепт (товар, количество, размер упаковки), реестр эталонов, якорь сцены.
   Если для любого товара нет эталонной фотографии лицевой стороны упаковки — СТОП и сообщи об этом.
2. Проверь: сумма (количество упаковок × печатный счёт) равна количеству рецепта;
   видов ≤ 4, упаковок ≤ 11, рядов ≤ 4, упаковок в ряду ≤ 4. Иначе СТОП.
3. Референсы по порядку: якорь, потом эталоны (не более 6 всего). Проверь SHA якоря.
4. Собери промпт: базовая часть + контракт по рецепту. Точный текст лицевой панели подавай побуквенно.
5. Сгенерируй. Проверь QA-офицером (3 прогона). Провал по блокеру → перегенерация с тем же промптом,
   максимум 3 оценённые попытки. Сбои воркера/зрения попытки не тратят.
6. Ни одна картинка без прохождения QA и без записи в манифест (модель, промпт, референсы с SHA,
   размеры, SHA результата) не уходит в карточку.
7. Никогда: свои цифры количества на упаковке, метки ретейлеров, лёд/снег, лишние предметы,
   «похожий» вкус, подставленная упаковка, правка логотипа якоря.
8. Не уверен — остановись и спроси человека. «Не смог проверить» = «не публиковать».
```

## 8. Что можно взять из репозитория как есть

- Логика раскладки и счёта: `uncrustables-box-planner.ts` (`validateRecipe`, `RENDER_LIMITS`),
  `uncrustables-render-contract.ts` (ряды, спилл на новые ряды, per-flavor замечания).
- Рендер + постпроверка байтов: `uncrustables-render-runner.ts`.
- QA: `audit/frozen-main-qa.ts` (переписать промпт под новые товары, логику сверки оставить).
- Автономный цикл с состоянием на диске и повтором: `scripts/_b2_auto.ts`; политика попыток:
  `uncrustables-auto-attempt-policy.ts`.
- Пример разового ремонта одного SKU: `scripts/_jfat_rebuild.ts` (plan → render → gallery → patch).
