# Смешанные наборы: несколько вкусов в одном листинге · 2026-08-06

> Связанные: [[bundle-factory-scale-plan-2026-08-02]],
> [[walmart-lane-audit-2026-08-05]], [[product-catalog-architecture]].

## Что произошло

Владелец написал бриф: **20 листингов по 8 банок, в каждом 2 вида супа по 4 банки
каждого**. Система прочитала из него только «20 × 8» и построила бы двадцать
восьмёрок **одного** вкуса — не тот товар, за полную стоимость, и выяснилось бы
это уже после публикации.

Потерялось не в модели. Числа берутся **разбором самого текста** в
`walmart-studio-request.ts`, а регулярные выражения знали только про количество
листингов и банок. Всё, что про состав, отбрасывалось молча.

## Что сделано

| Слой | Состояние |

| Чтение состава из текста (`parseWalmartPromptIntent`) | ✅ |
| Чтение состава моделью (`walmart-request-interpreter`) | ✅ |
| Согласование трёх чисел | ✅ |
| Перенос состава в задание (`components[]`) | ✅ |
| Обратная совместимость подписи | ✅ |
| Проверка достаточности доноров | ✅ |

### Правила, которые теперь держатся

- **Состав обязан сходиться:** `вкусы × банок_каждого = всего_банок`. Не сходится
  — сборка останавливается с `PACK_COMPOSITION_CONFLICT`, а не строит третье.
- **Хватает двух чисел из трёх** — третье выводится.
- **Один вкус не попадает в два листинга** за прогон: это дубль, за который
  Walmart наказывает.
- **Смешанному прогону нужно `листинги × вкусы` разных вариантов.** Раньше
  проверка сравнивала готовые варианты с числом листингов и объявляла «ничего не
  не хватает», пока прогон был реально коротким.

### Подпись задания — отдельная осторожность

Задание подписывается по своему содержимому. Добавление поля `components` в
подпись сломало бы **все** ранее запечатанные задания («bytes changed after
admission»). Поэтому обычный однотоварный мультипак подписывается ровно как
раньше — без этого поля, — а смешанный по своему составу, и подменить его после
подписи нельзя. Оба случая закреплены тестами.

## Чего ещё нет

`walmart-studio-draft-engine.ts` по-прежнему строит листинг из **одного** товара:
одна позиция состава, цена = цена_единицы × всего_банок, одна картинка, заголовок
одного вкуса. Поэтому прогон 2026-08-06 на 5 смешанных заданий дал 5 черновиков с
`components=1`.

Чтобы закрыть, нужно в движке:

1. составить позиции по всем `item.components` с их количеством;
2. считать себестоимость суммой по позициям, а не умножением одной цены;
3. собрать заголовок и описание, называющие **оба** вкуса и их количество;
4. сделать главную картинку из нескольких доноров;
5. проверить, что `represented_unit_count` считает сумму, а не `pack_count`
   одного товара.

Пятый пункт — тот самый предохранитель, который сегодня и не дал молча выдать
смешанный набор с картинкой одного вкуса.
