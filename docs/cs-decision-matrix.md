# Customer Service Hub — матрица решений (канон)

Версия 2026-10-30. Единственный канонический файл логики ответов покупателям.
Код обязан ему соответствовать; при расхождении прав этот файл и правила
владельца, код правится. Копия для вики Джеки: `wiki/business/cs-hub-decision-matrix.md`.

## 1. Источники и приоритет

1. Прямое указание владельца по конкретному кейсу (кнопка «Доработать» / комментарий).
2. Правила владельца: возврат только при нашей вине (27.10), вину не признаём (20.10),
   отправка только через VPS (20.10), формат карточки (20.10).
3. Плейбук из 7 месяцев переписки с GPT (`docs/wiki/customer-hub-owner-playbook.md`).
4. Таблицы A–I в промпте (`message-analyzer.ts`, SYSTEM_PROMPT).
5. Примеры: 175 реальных ответов из Seller Central + одобренные карточки.

Старые правила `cs-email-patterns.md` и `archive-knowledge/decisions.md`
(«frozen — только refund», «всегда предлагать refund», «A-to-Z угроза → немедленный
full refund», «CRITICAL → full refund», «вернуть при получении») владелец своими
не признаёт. Движок их НЕ читает, в коде их больше нет (см. §8).

## 3. Правило возврата (владелец, 27.10.2026)

Деньги возвращаются ТОЛЬКО при проблеме по нашей линии:
- (a) товар пришёл растаявшим / испорченным / повреждённым / просроченным,
  пришёл не тот или не весь товар — заявил покупатель или подтверждают факты;
- (b) нет первого скана перевозчика (этикетка есть, посылку не передали).

Даже тогда ПЕРВЫМ предлагаем замену (повторную отправку); деньги — только
если покупатель от замены отказался. Во всех остальных случаях — без возврата
и без частичного возврата. Покупателю не перечисляем, какие причины дали бы
право на возврат, не приглашаем вернуть еду через Amazon и никогда не пишем
«откажитесь от доставки».

## 4. Категории → решение → паттерн ответа

| Тип | Ситуация | Решение | Паттерн ответа (суть) |
|---|---|---|---|
| T1 | В пути, окно Amazon открыто | reassure | последний скан + конец окна; «если не придёт к …, напишите нам». Без возврата и A-to-Z |
| T1/T3 | Не доставлено, перевозчик тормозит, первый скан ЕСТЬ | redirect_amazon | извинение за неудобство, факты трекинга, отменить нельзя, ждать; если не придёт — Amazon / A-to-Z. Без возврата и замены |
| T1 | Нет первого скана (только этикетка) | replacement | «понимаем, что что-то пошло не так, отправим заново, придёт за два рабочих дня, подтвердите адрес». Вину не называем |
| T1 | После письма появилась отправка/скан | reassure | факт: отправлено {дата}, трек, 2 рабочих дня. Повторную отправку не обещаем |
| T2 | «Доставлено, но не получил», 1-е письмо | clarify | дата/время, место с фото/«Received by», где поискать по типу адреса |
| T2 | То же, повторно | redirect_amazon | «не можем вернуть деньги или заменить посылку, отмеченную доставленной» → A-to-Z |
| T3 | Опоздание, но доставлено целым | none | факты; без возврата |
| T4 | Растаяло/испорчено, доставлено вовремя | clarify → replacement | фото (коробка, термобокс, лёд, продукт); «не употребляйте и не замораживайте повторно»; после фото — замена |
| T4 | Растаяло после задержки перевозчика (>3 дн., Buy Shipping) | redirect_amazon | факты задержки, «не употребляйте», A-to-Z review |
| T4 | «Пришло замороженным», «выбросил по совету Amazon» | clarify | замороженный — не брак; что было на самом деле. Без автоматического возврата |
| T5 | Повреждено | clarify → replacement | фото; затем замена |
| T6/T7 | Не тот / не весь товар | clarify → replacement | фото этикеток и всего полученного; подтверждено — замена (без возврата еды) |
| T8 | Просрочено / нет даты | clarify → replacement | фото даты; подтверждено — замена |
| T9 | Дорогая доставка | none | термоупаковка, лёд, ускоренная доставка; свои затраты не раскрываем; отправленное отменить нельзя |
| T10 | Отмена до отправки | redirect_amazon | пусть подаст официальный запрос в Amazon, мы одобрим |
| T10 | Отмена после отправки | none | отменить нельзя; без возврата; без «откажитесь» |
| T11 | «Хочу возврат» без причины | clarify | спросить, что случилось; не обещать возврат |
| T12 | Не заказывал | redirect_amazon | в Amazon; без возврата от нас |
| T13 | A-to-Z угроза / подан | clarify / redirect_amazon | НЕ автоматический возврат; решает правило §3 |
| T14 | Угроза отзывом | clarify | не уступать; спросить о проблеме; отзыв не упоминать |
| T15 | Болезнь / отравление / FDA | investigate (стоп-лист) | сочувствие, «не употребляйте», фото продукта и даты; ни возврата, ни замены в черновике — решает владелец |
| T16 | Postage due | clarify | не платить; варианты от нас |
| T17 | Качество/вкус | no_refund | как T22 |
| T18 | Вопрос до покупки | info | факты; состав — только по этикетке |
| T19 | Возврат уже сделан | info | подтверждение, несколько рабочих дней |
| T20 | Повторная жалоба | по сути | без новых уточнений; замена только если §3 (a)/(b) |
| T21 | Платил за ускоренную, ушла обычная | none | «самый быстрый доступный вариант»; отменить нельзя; без возврата |
| **T22** | «Не понравилось / питомец не ест / передумал / не нужно / не знал про доставку» | **no_refund** | «нам жаль, что [корм не понравился питомцу], но это не повод для возврата; по политике Amazon продукты питания и корм возврату не подлежат». Без перечня причин для возврата, без приглашения вернуть, без «откажитесь» |

## 5. Запреты в тексте покупателю (с проверкой в коде)

| Запрет | Как проверяется |
|---|---|
| Признание вины («our error / on our side / it never left us / not the carrier's fault») | `FAULT_ADMISSION_RE` → автоматическая переписка |
| Возврат без основания по §3 | `REFUND_OFFER_RE` + `refundBasis()` → переписка, решение → no_refund |
| Возврат раньше предложения замены | то же → переписка, решение → replacement |
| «Откажитесь от доставки / refuse delivery» | `REFUSE_DELIVERY_RE` → переписка |
| Намёк, при каких причинах дали бы возврат | `REFUND_REASON_HINT_RE` → переписка |
| Выдуманные даты / статусы | fact-check дат (даты из правки владельца и свежих сканов считаются проверенными) |
| «Отправлено вовремя» и A-to-Z при отсутствии первого скана | правило NOT HANDED OVER + `transitFacts` |
| Эмодзи, ссылки, контакты, просьбы об отзыве, health-claims | `replyContentViolations` (автопилот) |
| «Safe to eat», спор о безопасности еды, просьба вернуть еду | промпт, HARD RULES |

## 6. Стоп-лист: только черновик, решает владелец

Деньги (возврат, частичный возврат), замена, A-to-Z и chargeback, порча,
болезнь/FDA, угроза отзывом, повторная жалоба (3+), не хватает обязательных
данных, неанглийский текст. Автопилот (когда включат) может сам отвечать только
на T1, T3, T16, T18 с решением reassure/clarify/none при риске LOW, проверенных
фактах, близком примере владельца и чистом тексте.
